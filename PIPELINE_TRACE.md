# PIPELINE_TRACE.md

Every box in the SPEQULA architecture diagram, traced to the code that implements it.
Repo state: branch `main`, HEAD `d720199`, traced 2026-08-27. Full test suite green (320 passed).

**Verdict key** — Full: works end to end in a running system. Partial: real code, but a named
part of the box is absent or unreachable. Stub: code exists and is tested, but no production
caller reaches it. Missing: no implementation.

**Headline:** 4 Full, 8 Partial, 3 Stub, 5 Missing out of 20 components. The left half of the
diagram (ingest → mapping → model) is largely real. The right half degrades sharply: the AI
Layer is a hardwired stub, the entire quality/exception subsystem has readers but no writers,
and four boxes — industry benchmarking, the domain intelligence layer, alerts, and potential
actions — have literally zero lines of code behind them.

## The three findings that matter most

**1. The quality subsystem is readers-without-writers.** This is one root cause producing four
degraded boxes. `write_exceptions` ([checks.py:63](src/quality/checks.py#L63)) has zero callers
outside `tests/`, and the five period-state transition functions (`validate_period`, `map_period`,
`reconcile_period`, `lock_period`, `restate_period`) have **zero callers in `src/`** — only
`get_current_period_lock` is read. So in a running system: the exception queue stays empty, data
health shows nothing, the pack's data-quality appendix is blank, periods never advance past their
initial state, and the sign-off gate can never trigger. Every one of these components is written,
tested and correct in isolation; none is wired to the pipeline. The tests pass because the tests
call the writers directly.

**2. Admission gates run after execution, not before.** [ask.py:135](src/semantic/ask.py#L135)
executes, [ask.py:151](src/semantic/ask.py#L151) inspects. The diagram's central safety claim —
gates standing between the model and the data — is inverted in code. Gate 7's row cap is computed
and thrown away. Execution does not assume the `model_reachable` role, so gates 2 and 5 are string
matching rather than Postgres grants. The author documents this honestly at
[ask.py:198](src/semantic/ask.py#L198); it is a known gap, not a hidden one. It is still not what
the diagram shows.

**3. Four boxes have no code at all.** Industry benchmarking / Tracxn, the domain intelligence
layer, alerts, and potential actions. Each is drawn with the same visual weight as the trial
balance check, which is tested to the rupee across 36 months. Three of the four are named in
`CLAUDE.md` §10 as explicitly out of scope with triggers that have not fired — meaning the
diagram and the project's own governing document disagree about what this system is. The
benchmarking box goes further than absence: `refusal.py` treats competitor questions as the
canonical example of something this system must refuse to answer.
